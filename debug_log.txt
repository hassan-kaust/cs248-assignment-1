DEBUG LOG - CS248 Assignment 1 (ray tracer), session of 2026-09-19
====================================================================

1. Gray plane not visible in orthographic mode
   Symptom: floor plane (point (0,-1.4,0), normal (0,1,0), color (0.5,0.5,0.5)) not shown.
   Cause:   ortho rays all have direction (0,0,1); dot(normal, dir) = 0, so the
            rays are parallel to the plane and Plane::intersect returns -1.
            The floor is seen edge-on. Correct behavior, not a bug.
   Action:  none. Assignment fixes the ortho direction (+z) and the plane
            height/color; it does not require the floor to be visible in ortho.

2. Plane added to the scene
   - ofApp.h:   added Plane* grayPlane member.
   - ofApp.cpp: grayPlane = new Plane(Vec3(0,-1.4,0), Vec3(0,1,0), Vec3(0.5,0.5,0.5));
                pushed onto scene as the 4th object and intersected in render().
   Normal (0,1,0) is an inference (assignment gives only y = -1.4 and the color).

3. Earlier local edit reverted
   - RayGenerator.cpp had b = -3.0f (changed the viewing-plane y extent, which
     breaks the spec's [-1.5, 1.5]). Stashed as "pre-revert local edits" and not
     restored.

4. Image rendered upside down (RayGenerator.cpp)
   Symptom: floor would appear in the top half of the window.
   Cause:   v = b + (t - b) * (j + 0.5) / ny mapped pixel row j = 0 (top of the
            image) to v = -1.5 (bottom of the viewing plane).
   Fix:     v = t - (t - b) * (j + 0.5) / ny. Extents kept at [-1.5, 1.5].

5. Floor still not visible after the fixes: stale binary
   Symptom: floor still missing in perspective mode.
   Cause:   bin/CS248-OF-template.app binary was built Sep 18 21:33, before
            the plane, perspectiveMode = true, and the flip fix.
   Fix:     ran `make` in the project directory, then relaunched.
   Result:  floor and shadows now visible in perspective mode (confirmed by
            screenshot).

6. Settings for this push
   - perspectiveMode = true in ofApp::setup() (perspective view shows the floor).

7. Shadow acne (black speckles on spheres/ellipsoids)
   Symptom: black speckles on all three objects in the perspective render.
   Cause:   shadow ray started exactly on the surface; the object re-hit itself
            (t > 1e-6 in float), so lit points were treated as shadowed.
   Fix:     Shade.cpp: shadow ray origin = hitPoint + normal * 1e-3.
   Result:  speckles gone (confirmed visually after rebuild).

8. Blue ellipsoid violated the handout (z must be negative)
   Symptom: found while writing the README; blue ellipsoid was centered at z = 1.8.
   Fix:     ofApp.cpp: center (0.6, -0.5, -0.4), radii (0.25, 0.2, 0.2), so it
            lies between the eye (z = -1) and the viewing plane (z = 0), inside
            x in [-2, 2], y in [-1.5, 1.5].
   Side effect: parallel rays started at z = 0, so an object with z < 0 would
            be behind every ray origin and never hit. RayGenerator.cpp: parallel
            ray origins now start at z = -1 (the viewpoint's plane), direction
            still (0,0,1).
